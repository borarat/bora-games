> 프로젝트 지식 파일. `학습게임_프로젝트지침_v3.md`와 함께 쓴다.
> **지침과 이 파일이 부딪히면 지침이 우선한다.** 특히 문항·채점·정답률 규칙은 지침 3~5장이 기준이고, 이 파일은 그것을 어떻게 보여 줄지만 정한다.

## 1. 시작 화면

**필수 구성 (위에서부터 순서대로)**

1. 영역 헤더 띠 (2-1)
2. 마스코트 이미지 + 게임 제목 + 학습 주제 부제
3. 「성취기준」 박스 — 교육과정 원문 코드와 문구 (지침 2-4)
4. 「게임 방법」 안내 박스 (점수·규칙 포함)
5. 개념·유형 목록 (해당 시). 판별 기준을 먼저 보여 주는 것은 좋다 (지침 3-7). 단 '어미 → 유형' 대응표처럼 정답을 바로 대조할 수 있는 표는 문제 화면에 띄워 두지 않는다
6. 시작 버튼 (필요 시 단계 선택 버튼)
7. 크레딧 박스
8. 개인정보 보호 안내 (5장)

**마스코트**

- 프로젝트 지식 `보라라샘_마스코트_base64_투명배경_4.txt`의 `IMG_BASE64` 사용
- 제목 **왼쪽**, 높이 90px, `border-radius: 12px`
- style은 문자열로 작성한다 (React·JSX 방식 금지 — 지침 6장)

**크레딧 박스 — 표기 형식 고정**

```
제작 · 보라라샘 · 전주서신중학교 교사 · siaawase@gmail.com
제작일 YYYY.MM.DD · 최종 수정 YYYY.MM.DD HH:MM
```

- 구분자는 가운뎃점(·). 슬래시나 콜론 형식 금지
- 직함은 **항상 "전주서신중학교 교사"** — '국어교사', '중등국어교사' 등 변형 금지
- 시각은 24시간제 `HH:MM` (`am11` 금지)
- '제작일'은 최초 제작 착수일로 **고정값**이다. 코드로 오늘 날짜를 넣지 않는다. '최종 수정'은 수정할 때마다 날짜+시각으로 갱신한다
- '최종 수정' 글자는 교사용 학습 데이터 목록의 진입점이다 (9장)

**레이아웃 — 여백 기준은 헤더 띠 아래부터**

```
영역 헤더 띠        ← 화면 맨 위, 위쪽 여백 0
  ↓ 48px
마스코트 + 제목
  ↓
본문
  ↓ 60px
화면 끝
```

- 띠 아래 48px — 제목이 띠에 붙어 보이지 않게 하는 최소치
- 하단 60px — 컨테이너를 화면 높이에 맞춰 늘리지 않는다. 내용 높이만큼만 차지하게 둔다
- 컨테이너 너비를 넓게 잡아 좌우 여백을 과하게 두지 않는다

**문제 화면 배치**

시작 화면 규칙(띠 아래 48px)은 문제 화면에 적용하지 않는다. 문제 화면은 띠 바로 아래에 진행바가 붙는다.

- 세로 가운데 정렬 — 문항이 적은 단계에서 화면이 위로 쏠리지 않게 한다
- 컨테이너 최대 너비 1100~1200px — 좁은 노트북 화면이 기준이다

## 2. 디자인 원칙

- 기본 폰트: **Noto Sans KR** (Google Fonts CDN) + 폴백 필수

  ```css
  font-family: 'Noto Sans KR', 'Malgun Gothic', '맑은 고딕', sans-serif;
  ```

- 제목에 두꺼운 서체(Black Han Sans 등) 금지
- 컬러는 국어 영역별 팔레트 (2-1)
- **문제 화면은 스크롤 없이 한 화면에.** 시작·결과 화면은 스크롤 허용, 단 시작 버튼은 첫 화면에 보이게
- 안내문·목록은 **문장이 바뀔 때만 줄바꿈** (한 줄에 여러 문장 금지)
- **어색한 줄바꿈 금지** — 1~2글자만 다음 줄로 넘어가면 폭 조정 또는 자연스러운 지점의 강제 줄바꿈. 크레딧 박스도 예외 아님
- 드래그 대신 버튼·탭 조작을 기본으로 한다 (마우스 없는 기기 대비). 드래그를 쓰면 **클릭 두 번(고르기 → 놓을 곳 누르기)** 방식도 반드시 함께 둔다. 이 대안이 있고 390px에서 확인되면 M1이 될 수 있다
- `zoom` 속성 금지 — 크기는 `max-width`와 폰트 크기로
- 고정 픽셀 대신 상대 단위 (`max-width:900px`, 글자 크기 `clamp()`)
- 버튼 격자 열 수는 미디어쿼리로 바꾼다
- **색으로만 정보를 주지 않는다.** 정답 초록·오답 빨강에 ✅❌를 붙이고, 유형 버튼에는 아이콘·이름을 둔다
- **다크모드 방어** — `html { color-scheme: light; }`
- 플레이 화면 우측 하단에 작고 은은하게 `제작 · 보라라샘 · 날짜` (구분자는 가운뎃점)
- **이모지·아이콘 점검** — 개념과 맞지 않는 비유(고·중·저모음에 주식 차트 📈📊📉)나 청소년 사이에서 다른 뜻으로 쓰이는 이모지(🫦 등)를 쓰지 않는다
- **톤** — 중학생 대상이다. 파스텔 과잉, "~박사!", "쏙!", "톡 누르세요" 같은 초등용 말투를 피한다

### 2-1. 국어 영역별 팔레트

| 영역 | 배경 | 강조색 | 텍스트(진한) | 카드 테두리 |
|---|---|---|---|---|
| 문학 | `#F2FBF7` (파스텔 민트) | `#2E9B79` | `#0F6E56` | `#DDF2E9` |
| 읽기 | `#F3F8FD` (파스텔 하늘색) | `#3B86C9` | `#185FA5` | `#E3EFFA` |
| 말하기·듣기 | `#FFFBEC` (파스텔 크림노랑) | `#F58A2E` | `#1B3A5C` (남색) | `#FBE9B8` |
| 쓰기 | `linear-gradient(165deg,#FFFFFF 0%,#FDF5F8 55%,#FAE9F0 100%)` | `#D4718F` | `#993556` | `#FAE4EC` |
| 문법 | `#F7F3FC` (연한 보라) | `#7C5CBF` | `#3C3489` | `#EAE5F8` |

**영역 헤더 띠 (전 게임 필수)**

- 시작 화면과 문제 화면 **모두** 컨테이너 최상단에 강조색을 꽉 채운 띠
- 글자는 흰색. 높이 36~40px, `border-radius: 12px 12px 0 0`
- 시작 화면: 왼쪽 `영역명` / 오른쪽 **모바일 등급 배지** (2-2)
- 문제 화면: 왼쪽 `영역명 · 학습 목표 한 줄` / 오른쪽 `문항 n / N · 점수`

```
┌──────────────────────────────────────────────────┐
│ 읽기                              💻📱 노트북·모바일 │  ← 시작 화면
└──────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────┐
│ 읽기 · 예문을 읽고 논증의 오류를 판별한다   12/26 · 150점 │  ← 문제 화면
├──────────────────────────────────────────────────┤
```

- 띠에는 성취기준 원문이 아니라 **학습 목표 한 줄**. 성취기준 코드·원문은 시작 화면 박스에
- 학습 목표 한 줄에 유형 이름이나 정답 단서를 넣지 않는다
- 폭 600px 이하에서는 목표 문구를 생략하고 영역명만
- 세로 공간을 쓰는 별도 꼬리말은 두지 않는다

**그 밖의 규칙**

- 문제 카드는 모든 영역에서 흰색(`#FFFFFF`) + 카드 테두리 0.5~1px
- 강조색은 헤더 띠, 버튼, 진행바, 콤보 HUD, 선택 상태에 사용
- 진한 텍스트는 제목·라벨용, 본문은 `#333` 계열
- 문법 게임의 기존 라벤더(`#f0eaf8`/`#7c5cbf`)는 호환되므로 색 소급 수정 불필요. **단 헤더 띠는 예외 없이 넣는다**
- **색과 마스코트만 영역별로 다르고, 화면 구조·함수명·로직은 전 영역 공통.** 구조가 갈라지면 공통 결함을 고칠 때 일이 영역 수만큼 늘어난다

### 2-2. 모바일 대응 등급 (전 게임 판정 필수)

노트북이 기본이고 모바일은 보조(집에서 복습, 노트북이 없을 때)다. 모든 게임을 모바일에 맞출 필요는 없지만 **등급은 반드시 정하고 표시한다.**

| 등급 | 대상 | 요구 사항 |
|---|---|---|
| **M1 · 완전 대응** | 버튼·선택형 (유형 판별, 분류, 객관식) | **390px 폭에서 실제로 확인**한 뒤에만 부여 |
| **M2 · 노트북 권장** | 입력·서술형 | 모바일에서 열리되 입력이 불편. 차단하지 않음 |
| **M3 · 노트북 전용** | 키보드로 조작하는 게임(갤러그 등), 정밀한 드래그·좌표 조작 | 모바일 접속 시 **시작 차단 + 안내** |

> 두더지·풍선처럼 **누르기(탭)만 하는 속도형은 M3가 아니다.** 휴대폰에서도 시작할 수 있게 둔다 (교사 결정 2026.10.01)

**배지 — 시작 화면 헤더 띠 오른쪽 끝**

| 등급 | 배지 |
|---|---|
| M1 | `💻📱 노트북·모바일` |
| M2 | `💻 노트북 권장` |
| M3 | `💻 노트북 전용` |

- 흰 글자 + 반투명 흰 배경(`rgba(255,255,255,.22)`)의 작은 알약 모양
- "PC"가 아니라 **"노트북"**
- 문제 화면 띠에는 넣지 않는다

**M1 판정 기준**

- 기준 폭 390px. **실제로 열어 확인한 뒤에만** 배지를 단다
- 확인 항목: 선택지가 한 화면에 들어오는지, 버튼 최소 44px, 배너가 화면을 벗어나지 않는지

**M3 차단 안내** — 폭 600px 미만이면 시작 버튼을 막고 띄운다

> 💻 이 게임은 노트북에서 열어주세요
> 마우스나 키보드로 조작하는 게임이라 휴대폰에서는 제대로 동작하지 않습니다.

> 등급은 블로그 글의 '사용 기기'와 게임목록 시트의 모바일 열에 그대로 쓰인다.

## 3. 피드백 연출

### 3-1. 정답 배너

| 요소 | 사양 |
|---|---|
| 배경 | 반투명 라디얼 딤 `rgba(0,0,0,.25)` |
| 등장 | 스프링 팝 `scale 0.3 → 1.15 → 1.0`, 약 350ms, bounce easing |
| 문구 | "정답!" 대형 텍스트 + 금색 그라데이션 + 외곽 글로우 |
| 획득 점수 | `+N` 카운트업 (기본점 + 콤보 보너스) |
| 광선 | 배너 뒤 conic-gradient 서서히 회전 |
| 색종이 | canvas 파티클 40~60개, 약 1.2초 |
| 반짝임 | 별/스파클 8~12개 |
| 사운드 | WebAudio 상승 아르페지오(도–미–솔–도, sine, 각 70ms) |
| 종료 | 약 900ms 후 자동 페이드아웃 |

- 배너 중에도 **Enter / Space / →** 로 즉시 다음 문항
- `prefers-reduced-motion`이면 파티클·회전 생략, 페이드만
- 재시도 정답에는 작은 배너(`다시 풀어 맞힘 +N`)만 띄우고 색종이·광선은 생략한다. 첫 시도 정답과 연출이 같으면 첫 시도의 의미가 흐려진다

### 3-2. 콤보 — 점수와 배너는 별개

- **콤보 보너스 점수**는 조건을 만족하는 **매 문항**에 붙는다 (지침 5장)
- **축하 배너와 축포**는 아래 시점에만

| 콤보 | 연출 |
|---|---|
| **3** | "3콤보! 🔥" 주황 그라데이션 배너, 축포 2발, 이모지(🔥✨) 12개 낙하 |
| **5 · 10** | "N콤보! 🎉🎊" 무지개 그라데이션 배너 + 확대·흔들, 축포 4발, 화면 테두리 글로우 펄스, 이모지 20개 |
| **15 · 20 · 25 …** | 5의 배수마다 "🌟 N연속! 최고예요" — 콤보가 오를수록 문구 크기와 축포 수를 키운다 |

- 매 문항 배너 금지 (26문항에서 연출에만 5~6분)
- 사운드: 3콤보 상승 3음, 5콤보 이상 팡파르 5음 + 화이트노이즈 축포음
- 콤보 배너가 터지는 문항에서는 정답 배너를 띄우지 않고, 한 배너에 정답 표시와 획득 점수 합계를 넣는다
- 화면 우상단 **콤보 HUD**(불꽃 + 숫자)는 콤보가 오를 때마다 펄스
- 콤보 배너도 Enter / Space / → 로 건너뛴다

### 3-3. 오답

- 빨간색 강조 + ❌ + 흔들림(shake) + WebAudio 하강음
- **힌트는 일반 팁과 구분되는 별도 스타일 박스** (힌트 내용 규칙은 지침 4-1)
- 재시도 횟수와 정답 공개 시점은 지침 5-1을 따른다 (보기 2개 문항은 재시도 없음)
- 정답 공개 때는 정답과 함께 **해설을 반드시** 보여 준다

## 7. 종료 화면

**자동 표시** — 마지막 문항 채점 후 학습 리포트가 즉시 뜬다.

**입력 필드**

- **학생 이름** — 실명(닉네임 아님), **필수**. 미입력 시 JPG 생성 불가, 안내 후 포커스 이동
- **학습 소감** — 선택
- 날짜·학습 소요 시간은 **자동 기록**. 소요 시간은 **마지막 문항을 채점한 시각**까지로 잰다 (내려받기 누른 시각이 아니다)
- 입력칸에서 모든 키가 정상 입력되어야 한다 (지침 6-1)

**버튼 위계 — 권하는 행동 하나만 색 채움(primary), 나머지는 테두리형**

| 상황 | 색 채움 | 테두리형 |
|---|---|---|
| 다음 단계가 남았을 때 | `다음 단계로` | 이 단계 다시 하기 · 시작화면으로 |
| 마지막 단계를 마쳤을 때 | `이 단계 다시 하기` | 시작화면으로 (`다음 단계로`는 숨김) |

- 오답노트·리포트 내려받기 버튼은 항상 색 채움
- `다음 단계로`는 마지막 단계에서 **숨긴다** (비활성으로 남기지 않는다)
- 이동 대상은 `현재 단계 + 1`로 계산한다. 단계 번호를 하드코딩하지 않는다

```js
const hasNext = S.stage < STAGES.length;
btn.onclick = () => startStage(S.stage + 1);
btn.style.display = hasNext ? '' : 'none';
btn.className = hasNext ? 'btn' : 'btn sec';
```

- 단계가 하나뿐이면 `다음 단계로` 없이 `이 단계 다시 하기`를 색 채움
- 중간 종료 시 제목은 "게임 완료!"가 아니라 "여기까지 풀었어요"로 한다

**안내 문구**

> 입력하신 이름과 소감은 서버에 저장되지 않으며, 리포트 이미지(JPG) 생성용으로만 쓰입니다.
> (온라인 모드일 때는 5장의 온라인 문구로 교체)

**학생용 복습 목록** — 종료 화면에 `📖 오늘 나온 문제 모두 보기`

- **이번 판에 실제로 출제된 문항만** 보여 준다 (전체를 열면 다시 플레이할 때 셔플이 무의미)
- 문제·정답·해설을 보여 준다. 속도형 게임일수록 필요하다
- 화면 모달로 충분하다 (다운로드 없음)

## 8. 산출물

### 8-1. 오답노트 JPG

**포함 항목 — 네 가지 모두 필수**: **유형 라벨** / 문제(예문) / **정답** / **해설**

- 문항 번호는 넣지 않는다 (셔플 출제에서 순번은 의미 없음)
- 화면 피드백에만 있고 이미지에 없는 정보가 있으면 안 된다
- 속도형은 잘못 누른 것과 놓친 목표를 모두 담는다
- 해설 줄 수를 반영해 블록·캔버스 높이를 계산한다 (고정 여백 금지)
- 해설은 정답보다 작고 흐리게 (13px / `#64748b` 정도)
- 오답이 없으면 축하 문구만 담은 짧은 이미지

### 8-2. 학습 결과 분석 리포트 JPG ★

**목적은 점수 통보가 아니라 진단이다.**

**구성**

1. 머리말 — 게임명 · 단계 · 이름 · 날짜/시각
2. 요약 수치 — 최종 점수(만점 대비) · 첫 시도 정답 · 다시 풀어 맞힘 · 못 맞힘 · 미응답 · 최고 콤보 · 소요 시간 · **정답률**
3. 총평 — 정답률 기준 한 문장 (지침 5-2 등급표)
4. 잘하는 유형 — 유형별 정답률 100%이고 채점된 문항이 2개 이상. `유형명 n/n`
5. 보완이 필요한 유형 — 유형별 정답률 50% 미만. `유형명 n/N`
6. 가장 먼저 공부할 것 — 유형 **하나** + 그 유형의 `tip`
7. 학습 소감 — 입력한 경우만
8. 꼬리말 — 성취기준(코드 + 원문) · 개인정보 안내 · 크레딧

**유형별 판정 규칙** (정답률 정의는 지침 5-2)

```
· 채점된 문항이 1개뿐인 유형은 잘함/보완 어느 쪽으로도 분류하지 않고 리포트에 표시하지 않는다.
  "판단 보류" 같은 태그도 띄우지 않는다.
· 가장 먼저 공부할 유형 = 채점된 문항이 2개 이상인 유형 가운데 오답 수가 가장 많은 유형
  (동점이면 정답률이 낮은 쪽, 그래도 동점이면 채점된 문항 수가 많은 쪽)
  해당 유형이 없으면 이 항목을 생략한다
· 오답이 없으면 "약점이 보이지 않아요. 다음 단계에 도전해 보세요"
· 전 유형 정답률이 50% 미만이면 유형을 나열하지 않고
  "유형 구분 자체를 다시 익힐 단계예요. 시작 화면의 유형 설명을 먼저 읽어 보세요"
· 채점된 문항이 0개면 리포트 대신 "풀어 본 문제가 없어요"
```

### 8-3. 공통 구현 규칙

- canvas + **시스템 폰트**(웹폰트는 canvas에서 깨진다) + 동기식 `toDataURL`
- 이미지 상단과 파일명에 **단계 · 이름 · 완료 날짜+시각**
- 파일명 예: `홍길동_학습리포트_1단계기본_20260914_1530.jpg` (게임 코드는 넣지 않는다)

## 9. 교사용 학습 데이터 목록 (전 게임 필수)

교사만 쓰는 **문항 전체 엑셀 내보내기**를 게임 안에 둔다. 속도형처럼 문항이 로직 깊숙이 들어간 게임일수록 필요하다.

### 넣을지 묻지 않는다 — 어떤 형태로 넣을지만 묻는다

> 이 게임의 학습 데이터 목록은 어떤 표로 만들까요?
> (기본안: 단계 열이 있는 문항 표 + 유형별 요약 / 문항 없는 게임은 규칙·레벨 구성표)

### 엑셀만 내려받는다 — 화면 표는 만들지 않는다

- 만드는 방식: **그 게임이 이미 쓰는 방식을 유지한다.** 새 게임은 HTML 표를 `.xls`로 저장하는 방식을 기본으로 한다 (가볍다. 엑셀이 '형식이 다르다'고 물으면 '예'를 누르면 열린다). 시트를 여러 개로 나눠야 하면 교사에게 SheetJS 인라인(파일이 수백 KB 커진다)을 쓸지 묻는다

- 구성: 문항 표(단계 열 포함) + 그 아래 유형별 요약 표. HTML 표 방식은 시트를 나눌 수 없으므로 한 시트에 담는다
- 열: 원본 id · 유형 · 문제(예문) · 정답 · 오답 보기 · 해설 · 힌트
- 마지막 줄: 성취기준 · 배점 규칙 · 총문항 수 · 크레딧
- 파일명 `[게임코드]_게임명_학습데이터목록_YYYYMMDD.xls`

### 진입 방법 — 크레딧의 '최종 수정' 글자 클릭

'최종 수정' 글자와 그 뒤 날짜·시각 전체를 한 번 클릭하면 엑셀이 바로 내려받아진다. 확인창 없음.

```html
<span id="lastMod">최종 수정 2026.09.15 20:58</span>
```
```js
const trigger = document.getElementById('lastMod');
trigger.style.cursor = 'default';
trigger.addEventListener('click', downloadTeacherXls);
```

- 커서·밑줄·색 변화·호버 효과를 주지 않는다. 별도 버튼·안내 문구도 없다
- **잠그지 않고 숨기기만 한다.** 학습용이지 수행평가용이 아니다. 암호·연타·길게 누르기 방식은 쓰지 않는다
  (예전 판의 '마스코트 2초 길게 누르기'는 폐지. 남아 있는 게임은 리모델링 때 이 방식으로 바꾼다)
- 암호 방식 금지: `type="password"`는 윈도우에서 한글 입력기가 꺼져 `보라라샘`이 `qhfkfktoa`로 들어간다

| | 교사용 | 학생용 (7장) |
|---|---|---|
| 언제 | 항상 ('최종 수정' 글자 클릭) | 게임을 끝낸 뒤에만 |
| 범위 | 전 문항 | 이번 판 출제분만 |
| 내용 | 문제·정답·오답 보기·해설·힌트·유형 | 문제·정답·해설 |
| 형태 | 엑셀 다운로드 | 화면 모달 |

## 11. 화면 검증 체크리스트 (지침 9장 C)

1. 시작 → 문제 → 결과까지 전 구간 진행
2. 정답 배너 / 3콤보 / 5콤보 / 오답 연출이 각각 뜨는지. 재시도 정답은 작은 배너인지
3. 키보드 3종(Enter / Space / →) 동작, 답하기 전에는 넘어가지 않는지
4. 문제 화면이 스크롤 없이 들어오는지, 어색한 줄바꿈이 없는지
5. 크레딧 '최종 수정' 글자를 클릭하면 엑셀이 바로 내려받아지는지, 커서·밑줄 변화가 없는지
6. 내려받은 엑셀에 문항·정답·오답 보기·해설이 빠짐없이 들어 있는지
7. `오늘 나온 문제 모두 보기`가 이번 판 출제분만 보여 주는지
8. 개인정보 안내가 시작·종료 화면과 JPG 2종 모두에 있는지
9. 다크모드에서 입력창과 글자가 정상인지
10. M1: 390px에서 실제로 열어 선택지가 한 화면에 들어오고 버튼이 44px 이상인지
11. M3: 600px 미만에서 시작이 차단되고 안내가 뜨는지
12. 종료 화면에서 다음 단계가 남았을 때 `다음 단계로`가 색 채움, 마지막 단계에서 숨김, 단계 번호 하드코딩 없음
13. 캔버스 이미지를 실제로 만들어 눈으로 확인
    - 모든 텍스트가 블록·캔버스 경계 안에 있는지
    - 내용 길이에 따라 블록 높이가 맞는지 (빈 공간·잘림 없음)
    - 오답 0개 / 1개 / 10개 이상 모두 정상인지
    - 이름·소감을 입력한 경우와 비운 경우 모두 정상인지
    - 잘하는 유형·보완 유형·학습 조언이 실제 결과와 맞는지
    - 채점된 문항이 1개뿐인 유형이 **표시되지 않는지**
14. 이모지·아이콘·말투 점검 (2장)
